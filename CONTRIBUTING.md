# Contributing

Issues and pull requests are welcome at
[odiseoteam/SyliusRbacPlugin](https://github.com/odiseoteam/SyliusRbacPlugin).

## The test application

The plugin is developed against a real Sylius application: `tests/TestApplication`, running on top
of `sylius/test-application`.

```bash
make init            # Containers, composer install, frontend build
make up / make down  # Start / stop
make php-shell       # A shell in the PHP container
make database-init   # Create the database and run migrations
make load-fixtures   # Sylius fixtures, including the roles this plugin seeds
```

The admin is then at `http://localhost/admin`, with `sylius@example.com` / `sylius` as a super
administrator.

> The `nginx` service binds port 80. If that port is taken, change it in `compose.override.yml`,
> generated by `make init` from `compose.override.dist.yml`, and not tracked by git.

## Running the checks

```bash
make phpunit         # PHPUnit
make behat           # Behat
make phpstan         # PHPStan, level max
make ecs             # Coding standard
make deptrac         # Layer dependencies
make composer-unused # Unused and shadow Composer dependencies
```

Without Docker, the same tools run directly:

```bash
vendor/bin/phpunit --testsuite unit      # unit, functional, integration, non-unit, all
vendor/bin/phpunit
vendor/bin/phpstan analyse -c phpstan.neon
vendor/bin/ecs check src tests           # --fix to autofix
vendor/bin/deptrac analyse --config-file=deptrac.yaml
vendor/bin/behat --strict --tags="~@javascript"
```

Non-JavaScript Behat scenarios run against the kernel and need no web server, but they do need the
frontend build, since the admin layout renders the Webpack entrypoints:

```bash
docker compose run --rm nodejs
```

Database credentials live in `tests/TestApplication/.env` and `.env.test`; inside Docker they are
overridden by `compose.override.yml`.

## What CI enforces

Every pull request runs the matrix, Sylius 2.0 / 2.1 / 2.2 × PHP 8.2-8.4 × Symfony 6.4 / 7.x on
MySQL 8.4, plus:

- **Route coverage.** Every admin route and API operation must be covered by a permission or
  declared excluded. This is the test that keeps the API from silently losing protection again.
- **Declaration hygiene.** No `route_permissions` or `excluded_routes` entry may name a route that
  no longer exists; nothing listed as public may actually be protected; every action hookable must
  be either gated or explicitly ungated.
- **Firewall coverage.** Every admin route of this plugin must fall inside
  `sylius.security.admin_regex`.
- PHPStan at level max, ECS, Deptrac and the Composer dependency analyser.

A red build on the coverage tests usually means Sylius added something, not that your change is
wrong. Just declare it and mention that in the pull request.

## Conventions

- Comments should explain **why**, not what. If the code already says it, don't repeat it.
- Anything version-specific about Sylius should go through `Compatibility\SyliusVersion`, not an
  inline version check.
- The `Legacy\` namespace can only be imported from `DataMigration\`; Deptrac enforces this.
- New permissions should be discovered, not hard-coded. If you find yourself writing a list of
  identifiers, check whether discovery should be producing them instead.
